# SaveVault Android 更新日志

Android 客户端的版本号独立于 PC（根目录 `CHANGELOG.md`，PC 程序会解析那一份，
所以 Android 的条目记在这里）。

## [0.6.0] — 2026-11-09

每台设备可以用自己的令牌连接 SaveVault 云端：丢了一台设备，只需在网页上把它
移除，其他设备照常同步。需要 SaveVault 云端 v1.7.0 或更新；旧的同步密钥仍然
可以继续用。从 0.5.0 可以直接覆盖安装。

### 新增

- **用配对码连接。** 设置 › 云端 新增“用配对码连接”：在 SaveVault 云端网页
  生成配对码后，在手机上输入服务地址和配对码，或者粘贴配对链接，也可以用系统
  相机扫描网页上的二维码直接打开 SaveVault。连接前会先显示服务器地址请你确认，
  防止伪造的二维码把存档引到别人的服务器上。配对得到的设备令牌用 Android
  Keystore 加密保存。
- **设备被移除后停止同步。** 在网页上移除（吊销）这台设备后，SaveVault 会停止
  自动备份和补传，发一条通知，并在设置里提示重新配对，不会反复重试。重新配对
  或换上新的同步密钥后自动恢复，“Wi-Fi 自动备份”的开关保持不变。
- **连接状态。** 设置 › 云端 显示当前是“已用设备令牌连接：设备名称”还是
  “正在使用共享同步密钥”。云端准备停用共享同步密钥时，这里会提示你配对本设备；
  已经停用时，会提示改用配对码连接。

### 改进

- 用手柄填写云端地址、同步密钥和配对码时，方向键上下可以离开输入框，走到下一个
  输入框和按钮。

## [0.5.0] — 2026-11-08

改名为 **SaveVault（存档库）**，换了新图标；同一款游戏在手机和 PC 上的存档
可以互相看到，并能显式地从另一台设备恢复。

> **从 0.4.0 升级**：0.5.0 起用 SaveVault 发布密钥签名。之前自己构建或用调试
> 签名安装的 0.4.0 不能直接覆盖安装，需要先卸载（本机快照、目录授权和云端配置
> 会清空；已经上传到 SaveVault 云端的版本不受影响，重新配置后可以恢复）。

### 新增

- **其他设备的存档。** 游戏详情的“版本”页列出同一款游戏在其他设备（手机、PC）
  上的存档：设备、平台、时间、版本数和冲突。只读取，不改动任何东西。需要
  SaveVault 云端 v1.6.0 或更新。
- **从其他设备恢复。** 选一台设备，把它的最新存档恢复到本机。恢复前会先把本机
  当前存档保存为安全快照；云端的版本不会被改动，之后的备份照常作为本机的新版本
  上传。存档位置能按类型对应时自动选好，对应不上时由你选择或跳过，绝不猜路径。
- **上传失败后自动补传。** 手动备份时云端暂时连不上，版本会先存在本机，联网后
  自动补传（最多重试 3 次）。补传时云端已有更新的版本，会保留为冲突副本、不会
  覆盖，在“同步与任务”里处理；关闭“新版本自动上传”后不再补传。
- **没有 Root 也能扫描整个内部存储**，并新增 ePSXe、MAME 存档识别；推荐的授权
  目录、按应用分组的来源页。
- **游戏封面**：所有来源都能显示封面（eShop 图源、已安装应用图标），内置离线
  Switch 游戏名。
- **Switch 2**：识别 `04…` 开头的 TitleID 和 Eden 的 Switch 2 分支（Eglantine、
  SX2A）。
- 备份后向 SaveVault 云端上报游戏身份（TitleID、PSP 编号、包名等），云端据此把
  各设备的存档归为同一款游戏。

### 改进

- 授权目录失效时显示中文原因，游戏库给出明确的处理提示。
- 后台补传、自动备份完成后，游戏状态立即更新，不用重启 App。

### 修复

- 设备名含中文等非 ASCII 字符时也能正常同步（按 RFC 8187 编码；需要 SaveVault
  云端的配套更新）。
